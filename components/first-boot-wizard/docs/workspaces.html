📁 Workspaces

Workspaces provide isolated environments for different cloud accounts and projects. Each workspace has its own credentials, region settings, and context.

Why Workspaces?

  • Prevent accidents - Never accidentally run commands against the wrong account
  • Credential isolation - Each workspace has its own encrypted credentials
  • Visual context - Terminal prompt shows which workspace is active
  • Read-only mode - Protect production accounts from accidental changes

Creating Workspaces

Basic Creation

nubifer-workspace create \
    --name production \
    --provider aws \
    --account-id 123456789012

With All Options

nubifer-workspace create \
    --name production \
    --provider aws \
    --account-id 123456789012 \
    --account-name "Production AWS" \
    --region us-west-2 \
    --read-only

Managing Workspaces

List All Workspaces

nubifer-workspace list

Switch Workspace

nubifer-workspace switch production

# Or use the shortcut
nw-switch production

Show Current Workspace

nubifer-workspace current

# Or use the shortcut
nw-context

Delete a Workspace

nubifer-workspace delete WORKSPACE_ID
⚠️ Warning: You cannot delete the currently active workspace. Switch to another workspace first.

Read-Only Mode

Protect production accounts by enabling read-only mode:

Enable Read-Only

nubifer-workspace readonly WORKSPACE_ID --enable

Disable Read-Only

nubifer-workspace readonly WORKSPACE_ID --disable
💡 Tip: When read-only mode is enabled, write operations (like aws ec2 terminate-instances) will be blocked with a warning.
