🔧 Troubleshooting

Common issues and solutions for NubiferOS.

Setup Issues

❌ "pass (password-store) not initialized"

The credential manager requires pass to be set up first.

Solution: Run the setup wizard: 
nubifer-setup-wizard
❌ "No GPG key found"

You need a GPG key to encrypt credentials.

Solution: Generate a GPG key: 
gpg --full-generate-key
Then initialize pass: 
pass init YOUR_GPG_KEY_ID
Or just run nubifer-setup-wizard which does both.
❌ GPG asks for passphrase repeatedly

The GPG agent isn't caching your passphrase.

Solution: Configure GPG agent cache time: 
echo "default-cache-ttl 3600" >> ~/.gnupg/gpg-agent.conf
echo "max-cache-ttl 86400" >> ~/.gnupg/gpg-agent.conf
gpgconf --kill gpg-agent

Workspace Issues

❌ "Workspace not found"

The workspace ID or name doesn't exist.

Solution: List available workspaces: 
nubifer-workspace list
Use the exact workspace ID or name shown.
❌ "Cannot delete active workspace"

You're trying to delete the workspace you're currently using.

Solution: Switch to a different workspace first: 
nubifer-workspace switch OTHER_WORKSPACE
nubifer-workspace delete WORKSPACE_TO_DELETE
❌ Environment variables not set after switch

The workspace switch command shows instructions but doesn't set variables.

Solution: Use eval to apply the environment: 
eval $(nubifer-workspace env WORKSPACE_ID)
Or open a new terminal after switching.

Credential Issues

❌ "Error: 'pass' command not found"

The pass package isn't installed.

Solution: Install pass: 
sudo apt-get install pass
❌ AWS CLI says "Unable to locate credentials"

Credentials aren't being injected into the environment.

Solution: Make sure you've:
  1. Created a workspace with nubifer-workspace create
  2. Added credentials with nubifer-creds add --type aws
  3. Switched to the workspace with nubifer-workspace switch
  4. Applied the environment with eval $(nubifer-workspace env ID)

Security Issues

❌ "Operation blocked: Workspace is in READ-ONLY mode"

The workspace has read-only mode enabled.

Solution: Disable read-only mode (if intentional): 
nubifer-workspace readonly WORKSPACE_ID --disable
Or switch to a different workspace for write operations.
❌ AppArmor blocking an application

AppArmor is restricting an application's behavior.

Solution: Check AppArmor status: 
sudo aa-status
View denied operations: 
sudo dmesg | grep apparmor

Getting Help

  • Documentation: /usr/share/doc/nubifer/
  • GitHub Issues: github.com/jessetop/nubiferOS/issues
  • Check logs: journalctl -xe

Reset Everything

If you need to start fresh with credentials:

# Backup first!
cp -r ~/.password-store ~/.password-store.backup
cp -r ~/.gnupg ~/.gnupg.backup

# Remove password store
rm -rf ~/.password-store

# Re-run setup
nubifer-setup-wizard
